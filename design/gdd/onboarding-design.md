### 0.2 口径定义（工程侧/美术侧统一口径，避免对不上）

> ⚠️ 本圆桌出现两个数字（本文档 **43**、美术侧 **48**），两者**不矛盾，只是统计口径不同**。以下为统一定义，后续一律引用「口径 A / 口径 B」而非裸数字。

| 口径 | 名称 | 定义 | 数值 | 明细 |
|---|---|---|---|---|
| **A** | **功能单元** | 玩家能**点 / 拖 / 读**的离散功能元素，去重后计数 | **43** | 6 控制按钮 + 3 速度按钮 + 3 工具按钮 + 2 任务卡按钮 + 8 预设 + 7 滑块 + 6 指标卡 + 8 里程碑格 = 43 |
| **B** | **DOM 可视块** | 口径 A **＋ 5 个纯展示/容器级 DOM 块** | **48** | 43 + `header` + `.dishwrap`（含 canvas/#hud/#evt）+ `#legend` + 曲线 canvas + 放大观察 canvas = 48 |

- 本文档的**分层门控以口径 A（43）为准**——因为只有"功能单元"需要按层释放；纯展示容器不门控。
- 美术侧视觉权重计算用**口径 B（48）**更合适——因为亮块/面积直接受容器影响。
- **门控公式**：L1 放开 口径A 中的 3 个（`#btnPlay` + `immune` 滑块 + `#btnHint`），其余 40 个全部 `data-tier` 门控。

## 1. 设计支柱（Design Pillars）

三条，用于裁决后续所有取舍（冲突时优先级从上到下）：

1. **「一次只教一件事」** — 屏幕上任何时刻，**可操作控件 ≤ 3 个**（L1）。认知负荷优先于功能完整。
2. **「每一次操作都要有台词」** — 玩家的任何输入必须在 ≤ 600 ms 内换回一句人话或一次视觉响应。反馈即时性优先于数值精确性。
3. **「完整面板是奖励，不是门槛」** — 复杂度本身是**可获得的成就感**（解锁即奖励），不是开局成本。保留全部系统，只改变**到达顺序**。

## 2. MDA 框架分析

现有设计在 **A（Aesthetics）** 层已经很强（旁白把数字变剧情），但 **M（Mechanics）** 层没有信息节流，导致 **D（Dynamics）** 无法发生。

### 2.1 Mechanics（机制）— 我们改什么

| 层 | 机制状态 |
|---|---|
| 现状 | 29 控件 / 6 指标 / 8 里程碑 在 T=0 全部 `display:visible`，且可操作 |
| 改后 | 引入 `tier` 门控：每个可解锁元素带 `data-tier` 属性，由 `body.tier-N` 控制可见性 |
| 新增机制 | ① 引导状态机 `Guide` ② 术语改写层 ③ 反馈增强（脉冲/定格/幽灵轨迹）④ localStorage 记忆 |

### 2.2 Dynamics（动态）— 期望涌现的玩家行为

| 目标动态 | 触发机制 |
|---|---|
| "我先动一个看看" | L1 只留 1 根滑块 + 一根手指的指引 |
| "原来动这个会发生那个" | 每次滑块 input → 事件条立刻回一句因果旁白 |
| "我想把面板开全" | 解锁进度可见（`tier` 徽章 + toast「新解锁：化疗药剂」） |
| "我想再试一次能不能更好" | 幽灵轨迹 + 星级 + 里程碑收集 |

### 2.3 Aesthetics（美学）— 玩家最终获得的体验

- L1：**发现感（Discovery）** — "哦，原来这是这么回事"
- L2：**表达感（Expression）+ 挑战（Challenge）** — "我要用我的调法赢"
- L3：**胜任感（Mastery）+ 收集（Collection）** — "我全通了 / 我全收了"

> **关键改动**：把 Aesthetics 的重心从"看一盆漂亮的细胞"迁移到"我的操作有后果"。后者才产生趣味。

## 4.5 L1 与 `boot()` 开局逻辑的冲突处理【设计决策 · 关键】

### 4.5.1 冲突是什么

源码 `boot()` 末行（L3539）：

```js
renderMiles();
startMissionByIndex(0);      // 开局直接进入第一道实验题
```

即：**玩家看到的第一屏已经是「守住防线」这道判据严谨的任务**（`tumorPct<28% && malig<45`，需守住 200 轮）。这与 L1「极简上手」直接冲突——

| 冲突点 | 具体表现 |
|---|---|
| 认知层 | L1 应只教"这是坏细胞 + 你有一个杠杆"，但任务卡一上来就给**复合判据**（两个条件 + 时长），新人无法解析 |
| 情感层 | 首屏即"考试"：进度条 + 剩余轮数 + 星级，**先给压力后给能力**，与"30 秒上手"背道而驰 |
| 逻辑层 | `startMission` 会 `Object.keys(m.env)` 把 6 个因子**全部改写**（含 L1 隐藏的 5 根），玩家会看到"我没动别的，数值自己变了"的困惑 |

### 4.5.2 推荐方案：**L1 用同一道「守住防线」，但切换为「教学模式」而非特制新题**

**推荐：不新增第 7 道题，也不停用任务系统；而是给 `MISSIONS[0]` 加一个 `tutorial: true` 标记，L1 下以「教学模式」渲染。**

理由（三条，按权重排序）：

1. **不增加内容成本，也不违反"不推翻现有玩法"红线**
   特制一道新题 → 要写 goal/pass/probe/turns + 文案 + 数值调平，等于新增内容；而且玩家通完教学题后还要再面对「守住防线」，**同一件事做两遍**，反而累赘。

2. **「守住防线」本身天然适合当教学题——它的判据就是"推免疫"**
   已核对源码：`env: { immune: 62, ... }`，`pass: tumorPct<28 && malig<45`。即**玩家的第一次操作（把免疫推到 60+）本身就推动 `pass()` 成立**。换句话说，这道题的**正确答案 = L1 唯一教的那个动作**。这是最理想的引导-玩法同构：玩家不是在"做练习"，而是在"打真游戏且刚好赢了"。

3. **保护"第一局胜利"的真实性**
   如果 L1 用一道"假题"（或沙盒无目标），玩家赢的是练习；用「守住防线」，玩家赢的是**正式实验记录里的第一个里程碑**（`m_guard`），`experimentRecords` 立刻 +1。SDT 胜任感的兑现更硬。

### 4.5.3 L1 下「教学模式」与正常模式的具体差异

| 项 | 正常 `renderMission()` | L1 教学模式 | 实现方式 |
|---|---|---|---|
| 任务卡内容 | 任务名 + 副标 + 判据 + 进度条 + 星级 + 剩余轮 + tip + 2 按钮 | **任务名 + 改写后的目标句 + 进度条**（其余全隐） | `enterL1Layout()` 用 `style.display` 隐藏 `#mStars/#mLeft/#btnNext`；改 `#mGoal` 文案 |
| 判据呈现 | 「把肿瘤占比压到 28% 以下，并坚持到时限结束」 | **「把坏细胞比例压到 28% 以下」**（**去掉"并坚持到时限结束"** —— 时长概念延后到 L2 教学） | 文案层：按 `tier` 选择 `mGoal` 文案，**不改 `pass()` 判定** |
| `hold` 语义 | 需守住到 200 轮 | **仍按 `hold=true` 真实结算**，但 UI 不显示轮数，避免"我要等 200 轮"的畏难 | 逻辑零改动，只隐 UI |
| `tip` | 显示 | 隐藏（L1 用 `#hint2` 引导气泡替代） | 隐藏 `#mTip` |
| 目标文案来源 | `mission.goal` | **新增 `mission.goalL1` 字段**（仅 guard 需要，其余题无） | 在 `MISSIONS[0]` 加一个字段，改动量 = 1 行 |
| 6 因子初值 | 全 6 值被 `startMission` 改写 | **照常改写**（`E` 对象）——但 L1 只暴露 immune 一根，其余不可见，**无困扰** | 无需改 `startMission` |

> **关键**：`startMission(0)` 的**逻辑一行不改**。差异全部在**渲染层**（隐藏元素 + 换文案）。这保证 L2/L3 复用同一套结算逻辑，也让 §12 验收项 A10（数值未被改动）天然成立。

### 4.5.4 被否决的两个替代方案（记录理由）

| 方案 | 否决理由 |
|---|---|
| **B. L1 不启用任务系统**（纯沙盒，`mission=null`） | ① 玩家赢了没有任何记录，`m_guard` 里程碑要等 L2 再打一次，**重复劳动**；② 沙盒无目标 = 又回到"看画"的老问题，正是本次要修的；③ 从"无任务"切到"有任务"需要一次额外的模式切换动画与说明，**增加认知成本而非减少** |

```js
var GUIDE_KEY = 'vcl.guide.v1';

function guideLoad() {                    // localStorage 可能被禁用（隐私模式/iframe）
  try {
    var raw = localStorage.getItem(GUIDE_KEY);
    if (!raw) return null;
    var o = JSON.parse(raw);
    if (!o || typeof o.tier !== 'number') return null;   // 结构校验：防损坏/篡改存档
    return o;
  } catch (e) { return null; }            // 禁用/损坏/配额 → 一律走首次访问路径
}
function guideSave() {
  try { localStorage.setItem(GUIDE_KEY, JSON.stringify(GS)); }
  catch (e) { /* 静默忽略：写不进就只在内存里记，绝不打断游戏循环 */ }
}

var saved = guideLoad();
var GS = saved || {
  tier: 1,            // 当前层：1 | 2 | 3
  expert: false,      // 是否专家模式
  sliderTouched: {},  // {nutrient:1, immune:1, ...} 记录碰过哪些因子
  touchCount: 0,      // 累计拖动次数（含重复）
  missionsWon: 0,     // 已通关任务数
  step: 0,            // 引导步骤指针 0..3（注意：与源码全局的回合数 `step` 同名但不同义，见下）
  firstRunDone: false,
  seenLysis: false
};

/* ---- 度量函数（供触发条件判断）---- */
function distinctSliders() { return Object.keys(GS.sliderTouched).length; }

/* ---- 唯一的状态跃迁入口 ---- */
function setTier(n, why) {
  if (n <= GS.tier) return;
  GS.tier = n;
  guideSave();
  applyTier();                                        // 见 §11.2
  showEvent('🎉 新解锁：' + why + ' —— 右侧面板已展开。');
  toast('新解锁：' + why);
}

/* ---- 触发条件（每次事件后调用）----
   注意命名：本函数里的 `step` 是**源码全局的回合数**（`var step`，每演化一帧 +1）；
   `GS.step` 才是引导步骤指针。二者生命周期完全不同，勿混。 */
function checkTierUnlock() {
  if (GS.expert) return;

  /* L1 → L2：完成第 1 题，或（拖动 ≥5 次 且 已跑满 60 回合）
     ⚠️ 不能用 distinctSliders()：L1 只暴露 immune 一根滑块，永远 <2。
        Explorer 型玩家的第二条路改为「反复拖同一根」，故用 touchCount。 */
  if (GS.tier === 1) {
    if (GS.missionsWon >= 1) {
      setTier(2, '环境因子 + 点细胞看看');
    } else if (GS.touchCount >= 5 && step >= 60) {
      setTier(2, '环境因子 + 点细胞看看');
    }
  }
  /* L2 → L3：完成第 3 题，或 5 根可用因子全碰过
     ⚠️ 不能用 >=6：`变异速度`本身是 L3 才解锁的，L2 阶段最多碰到 5 根
        （immune/nutrient/oxygen/chemo/virus），阈值 6 同样不可达。 */
  if (GS.tier === 2) {
    if (GS.missionsWon >= 3) {
      setTier(3, '全部实验系统');
    } else if (distinctSliders() >= 5) {
      setTier(3, '全部实验系统');
    }
  }
}
```

### 7.4 实施方式：**改 DOM 文案，保留原常量**（采纳 team-lead 意见）

**明确推荐：只改"显示层"，绝不改"数据层"。** 理由已用源码验证：

| 被改对象 | 是否影响逻辑 | 源码证据 |
|---|---|---|
| `ENV_DEF[i].label` / `.hint` | ❌ 纯显示 | L669 仅用于拼 `innerHTML`；因子逻辑走 `data-env` 属性与 `E[id]`，**与 label 无关** |
| `.m .k`（HTML 静态文本） | ❌ 纯显示 | 数值由 `#mTumor` 等 id 驱动，label 是死文本 |
| `MILES[i].t` | ❌ 纯显示 | L637/L644 仅用于 `toast` 与 `innerHTML` |
| `mission.name/sub/goal/tip/hint` | ❌ 纯显示 | L531/546/552/606/610 全是 `showEvent`/`innerHTML` |
| `judgeStage().name/desc` | ❌ 纯显示 | 入参是 `(tumorPct, malig)` **数值**，返回对象仅用于 L2205 拼 `innerHTML` |
| `PRESETS[i].name/sub` | ❌ 纯显示 | L3340/3352/3359 仅拼 HTML/文案 |

**反例——绝对不要动的（一动就崩）**：

| 名字 | 为什么不能动 |
|---|---|
| `M.tumorPct` / `M.confluence` / `M.malig` / `M.total` | `MISSION.probe()/pass()` 的判据直接用它们（L445–496） |
| `E.immune` / `E.oxygen` / `E.chemo` … | 模拟内核按 key 读值（`ENV_DEF` 的 `id`，不是 `label`） |
| `type:'tumor'` / `'mutant'` / `'immune'` / `'normal'` | `updateMetrics` 的 `if (c.type === 'tumor')` 分支 |
| `data-env="immune"` / `data-tool="kill"` | DOM 事件选择器依赖 |
| `MISSIONS[i].id` / `PRESETS[i].id` / `MILES[i].id` | `mileGot[id]`、`unlockMile('m_'+mission.id)` 的键 |

**推荐实现（零风险路径）**：直接**原地改写字符串字面量**，而不是运行时 `applyTerminology()` 遍历替换。

- 原地改写 = 编辑源码里那 16 个核心标签位的字符串 → **无运行时开销、无漏替换风险、可被 A9 Grep 验收**。
- 运行时替换（`applyTerminology()` 遍历 DOM 做 `replace`）= 要在 `renderMission()` 每次重绘后重跑，且会漏掉动态拼接的文案（如 `renderFate` 的 `extra`），**更容易漏**。

> **结论**：`applyTerminology()` **降级为可选**。主路径是**直接改字符串字面量**（54 处用户可见里的核心 16 处 + 其余嵌在长文案里的 38 处一并重写）。若用户选择 D2 方案 B（只改主标、旁白保留术语），则只改 16 处核心标签位。

#### 9.2.1 无痕模式 / 存储被禁用时的降级行为（明确规格）

**一句话规格：读不到存档 → 引导从头走一遍；写不进存档 → 静默忽略。全程不报错、不白屏、不弹任何错误提示。**

| 事件 | 期望行为 | 玩家体感 |
|---|---|---|
| `localStorage.getItem` 抛异常 | `guideLoad()` 捕获 → 返回 `null` → 用默认 `GS`（`tier=1`） | 引导从 L1 第一步开始，**完全正常** |
| `localStorage.setItem` 抛异常（配额满/禁用） | `guideSave()` 捕获 → **静默 return** | 无任何提示；本次会话内 `GS` 仍是内存对象，**tier 在会话内照常推进** |
| `JSON.parse` 失败（存档损坏） | 捕获 → 返回 `null` → 默认 `GS` | 同首次访问 |
| 无痕模式（每次会话独立） | 表现为"每次打开都从 L1 开始" | **这是可接受的降级**——无痕用户本就不期待持久化 |

```js
function guideLoad() {
  try {
    var raw = localStorage.getItem(GUIDE_KEY);
    if (!raw) return null;
    var o = JSON.parse(raw);
    /* 结构校验：防止老版本/被篡改的存档导致后续 .tier undefined */
    if (!o || typeof o.tier !== 'number') return null;
    return o;
  } catch (e) { return null; }          // 禁用/损坏/配额 → 一律走首次访问路径
}
function guideSave() {
  try { localStorage.setItem(GUIDE_KEY, JSON.stringify(GS)); }
  catch (e) { /* 静默忽略：写不进就只在内存里记，绝不打断游戏循环 */ }
}
```

**为什么必须强调"不报错"**：源码是**单个 IIFE**（L385 `(function(){...})()`）。IIFE 内任何一个未捕获异常都会**终止整个初始化流程**，后果是 `boot()` 不执行 → 加载遮罩 `#loading` 永不隐藏 → 玩家看到**永久转圈的"正在培养细胞…"**（表现为白屏/假死）。这是本次改动里**唯一可能造成致命故障**的点，因此 §12 验收项 A8 单列强制验证（DevTools → Application → Storage 全部禁用后加载）。

> **补充事实**：源码当前**完全没用 localStorage**（已全文确认 `grep localStorage` 零命中），所以这是从零新增的能力，`try/catch` 不是"防御性编程"，而是**必需的正确性条件**。

### 11.2.1 L1 是否有足够"掌控感"？—— 回应美术侧质疑【设计判断】

**美术侧质疑**：L1 只靠一根免疫滑块，是否足以建立"我能影响它"的信心？
**我的回答：足够 —— 但前提是必须满足三个条件，缺一不可。这三个条件我已全部设计入 L1。**

| 条件 | 为什么它是关键 | 在本文档哪里 |
|---|---|---|
| **① 唯一杠杆必须"立竿见影"** | 免疫滑块是全作**反应最快**的因子：拖动后 1–2 个演化回合内，`updateMetrics` 就会让「坏细胞比例」下降，且培养皿里**立刻长出绿色免疫细胞**（可见实体，不只是数字变）。这是"我动了 → 世界变了"的最短因果链 | §6 Step 1 |
| **② 反馈必须可见于培养皿（而非只在数字里）** | 只看数字变化 ≠ 掌控感。绿色免疫细胞是**新增的可见实体**，玩家能"看见自己的手" | §6 Step 1 反馈③ |
| **③ 第一次操作必须直接导致胜利** | 这是最强的掌控感证明：「守住防线」`env.immune=62`，玩家推一下 → `pass()` 成立 → 赢。**操作与结果 1:1 对齐**，没有中间噪音 | §4.5 |
| **④ 兜底：一根滑块带来的可控性比"零工具"更高** | 工具（点选/划痕/接种）在语义上是"探索性动作"，后果不明确；而滑块是**方向性动作**（推高 = 更强），后果可预期。对"掌控感"而言，**可预期 > 可操作** | — |

**反方（美术侧立场）为何不必采纳**：他的诉求是"给一个立刻见效的动作"——**这一点我完全同意**，只是实现元素不同。若在 L1 加一个工具，会同时破坏三件事：① 违反 L1「可操作控件 ≤ 3」硬约束；② `划痕清除` 是破坏性操作（对不知道"细胞是什么"的玩家语义反直觉）；③ 稀释唯一杠杆的焦点，玩家会不知道该深挖哪个。**用滑块满足同一诉求，是更优解，而非妥协。**

> **若用户实测后仍觉得掌控感不足**，我的备选（按优先级）：**B1** 在 Step 1 后加一次性"手柄引导"（拖动时滑块轨道高亮脉冲 + 拖到位时 `burstFx` 一圈白环）；**B2** 允许 L1 提前开放 `点细胞看看`（**非破坏性**，只读工具，成本最低）。**B2 优于 B1**——因为它给的是"探索权"而非又一个动作。此备选仅在实测证伪时才启用。

> **本版新增的命名说明**：`LAYERS` 常量见 §11.9（与 `data-tier` 的统一方案）。

### 11.3.6 `#inspCard`（细胞放大观察）的层级归属【回复美术侧】

**同意美术侧判断：L1 直接不显示（连锁壳也不显示），L2-a 才出现。**

理由：
1. **它是 L1 的第一噪声源**——面积约 300×300，且 `background:#0d0e10` 对比强、空载时是一个纯白提示块（"点击培养皿里任意一个细胞…"），**零信息 + 高亮度**，直接违反 L1「可见视觉块 ≤ 6」的目标。

|---|---|---|---|
| 引导层级（本文档） | T1 | **`T1 / T2 / T3`**（Tier） | **事件驱动**的进度门控 |
| 视觉层（美术侧） | T2 | **`VL1 / VL2 / VL3`**（Visual Layer） | **时间窗**内的一次性入场节奏 |

**本文档后续如无特别说明，`L1/L2/L3` 一律指引导层级（= T1/T2/T3）。**

#### 11.7.2 ⚠️ 关键纠正：视觉层**不能是纯时间窗**，必须是事件驱动

美术侧当前定义是 **VL1 = 首屏 0–1s / VL2 = 1–3s / VL3 = >3s**。**这个模型与三层引导的根本目的冲突**：

- 若 `>3s 全部显示`，那么玩家开门 3 秒后**依然面对 43 个控件** —— 等于我们**什么都没修**。原诊断的根因就是"复杂度没有分层"，而时间窗只是**延后 3 秒**，不是分层。
- 正确模型：**视觉权重用时间窗（入场节奏），元素可见性用事件门控（Tier）**。两者正交，各管一段。

| 维度 | 归谁管 | 规则 |
|---|---|---|
| **元素是否可见** | T1（本文档） | 由 `GS.tier` + `data-tier` 决定，**事件驱动**（完成 N 题 / 碰过 N 根滑块） |
| **入场时的动画节奏** | T2（美术侧） | 由时间窗决定（解锁瞬间 0–1s 焦点滑入 / 1–3s 支撑层淡入），**只在解锁那一帧触发一次** |

> 即：美术侧的 `VL1/VL2/VL3` 应被重定义为**"同一次解锁事件内的三级入场动画节奏"**，而非"游戏开局的三个时间窗"。这样两套分层就能叠加而非打架。

#### 11.7.3 逐条回答美术侧 3 个问题

**Q1：操作工具（划痕清除/接种病毒）第 1 阶段就给吗？**
→ **不给。L1 零工具。** L1 的"能立刻看见效果的动作"由**免疫滑块**承担（拖动 → 培养皿立刻长出绿色免疫细胞 → 坏细胞比例下降）。理由：
- L1 硬约束是「可操作控件 ≤ 3」，一个工具就占满 1/3 预算；
- `划痕清除` 是**破坏性操作**（`scrapeAt` 直接把细胞设为 `dying`）——让一个还不知道"细胞是什么"的玩家去"划掉细胞"，语义上反直觉；
- `接种病毒` 需要先理解"病毒只杀坏细胞"，属 L2-d 之后。
**工具分批**：`点细胞看看`(L2-a) → `手动刮除`(L2-c1) → `放病毒`(L2-d)。这与美术侧"先给一个能看见效果的动作"的**意图一致**，只是实现该意图的元素换成了**非破坏性的滑块**。

**Q2：环境因子滑块一次性全给还是分批？**
→ **强烈同意分批，且我的批次更细：1 → 3 → 4 → 5 → 6**（比美术侧的 3→6 更渐进）。

| 阶段 | 累计滑块 | 新增 |
|---|---|---|
| L1 | **1** | 免疫兵力 |
| L2-a | **3** | + 养分、含氧量 |
| L2-c1 | **4** | + 化疗药量 |
| L2-d | **5** | + 病毒剂量 |
| L3 | **6** | + 变异速度 |

**Q3：曲线图（细胞数变化）属于阶段 1 吗？**
→ **不属于，归 L2-a。** 且**同意把 canvas 底色压暗**：源码现为 `background:#16181b`（L337 inline style），建议再压到 `#121316` 并将描边线宽 -0.5px，降低它的视觉抢焦。它在 L1 应显示**锁壳**（`开始第一次实验后解锁`）。

**Q4：`#inspCard`（放大观察）归属？**

#### 11.7.4 给美术侧的"锁壳"可访问性交叉确认

### 11.9 【统一方案】`LAYERS` 常量 ↔ `data-tier` 属性（回应 team-lead Q5）

**team-lead 的问题**：美术侧提议做 `LAYERS` 常量对象（每个 id 声明属哪层），与我方案里的 `data-tier` HTML 属性**是否重复**？还是 `LAYERS` 生成 `data-tier`？

**答案：两者不是二选一，而是「单一事实来源 → 派生」的关系。`LAYERS` 是唯一真值，`data-tier` 由它生成（而非手写在 HTML 里）。**

理由：
1. **手写 `data-tier` 有 40+ 处，且分散在 HTML 与 JS 里**（`ENV_DEF` 的 6 条、`MISSIONS`、`PRESETS`），任一处笔误都会造成"这层解锁了但那个没有"的错位，且难以发现。
2. **边界一定会调整**（用户已就 D1–D4 改过一轮），改一处 `LAYERS` 比找 40 处 `data-tier` 安全得多。
3. **纯 CSS 门控仍需 `data-tier` 属性**，所以要保留属性——但让它**由 JS 在启动时统一注入**，而不是手写。

**统一规格（单一事实来源）**：

```js
/* ============================================================
   3.45 分层归层表 —— 唯一真值来源
   语义：值 = 「该元素从第几层开始可见」
   改边界 = 只改这张表，不动 HTML、不动 CSS、不动其它 JS
   ============================================================ */
var LAYERS = {
  /* --- 常驻（L1 起可见）--- */
  '#dish': 1, '#hud': 1, '#evt': 1, '#hint2': 1, '#missionCard': 1,
  '#metricGrid mTumor': 1,           // 仅 mTumor 单卡
  '[data-env="immune"]': 1,
  '#btnPlay': 1, '#btnHint': 1,
  '#btnExpert': 1, '#tierBadge': 1,  // 逃生阀，L1 起常驻

  /* --- L2-a --- */
  '[data-env="nutrient"]': 2, '[data-env="oxygen"]': 2,
  '[data-tool="inspect"]': 2,
  '#chartCard': 2, '#fateCard': 2, '#inspCard': 2,
  '#metricGrid mConf': 2,

  /* --- L2-b --- */
  '#mileCard': 2, '#metricGrid mMalig': 2, '#riskBand': 2,
  '.preset[data-pid="normal"]': 2, '.preset[data-pid="immune"]': 2,

  /* --- L2-c --- */
  '[data-env="chemo"]': 2, '[data-tool="kill"]': 2,
  '#btnStep': 2, '#btnReset': 2,

  /* --- L2-d --- */
  '[data-env="virus"]': 2, '[data-tool="infect"]': 2,
  '#metricGrid mVirCard': 2, '#metricGrid mFreeCard': 2,

  /* --- L3 --- */
  '[data-env="mutation"]': 3,
  '#speedCard': 3, '#legend': 3, '#hud2': 3, '#mStars': 3, '#mLeft': 3,
  '#btnNext': 3, '#btnSeed': 3, '#btnVirus': 3, '#btnFluo': 3,
  '.spd': 3, '#metricGrid mTotal': 3,
  '.preset': 3   /* 兜底：其余 6 个预设；已单独声明的 2 个优先 */
};

/* 启动时注入：把 LAYERS 派生为 DOM 上的 data-tier 属性 */
function injectTiers() {
  Object.keys(LAYERS).forEach(function (sel) {
    var tier = LAYERS[sel];
    /* selector 形如 "#metricGrid mTumor" → 处理"容器内的 id"写法 */
    var parts = sel.split(' ');
    var nodes = parts.length === 2
      ? (function () {
          var box = document.querySelector(parts[0]);
          return box ? box.querySelectorAll('#' + parts[1]) : [];
        })()
      : document.querySelectorAll(sel);
    Array.prototype.forEach.call(nodes, function (n) {
      n.setAttribute('data-tier', tier);
    });
  });
}
```

**三者分工（一句话）**：

| 层 | 角色 | 谁写 |
|---|---|---|
| `LAYERS` 常量 | **唯一事实来源**：id → 起始层 | 设计（本文档 §11.9），**改边界只改这里** |
| `data-tier` 属性 | **派生结果**：`injectTiers()` 启动时注入 DOM | 由 JS 生成，**人不手写** |
| `body.tier-N` + CSS | **执行**：`display:none !important` | 美术侧 CSS（已就绪，一行不用改） |

**流程**：`boot()` → `injectTiers()`（读 `LAYERS` 打标）→ `applyTier()`（切 `body.className`）→ CSS 生效。
**边界调整 = 改 `LAYERS` 里的一个数字**，完全满足美术侧"只改一行"的诉求，同时避免 40 处手写属性。

> **与 CSS 的关系**：CSS **不需要知道 `LAYERS`**，它只认 `data-tier` 属性——所以 CSS 是稳定的，`LAYERS` 是可变的。这正是"单一事实来源"的价值。
> **一处例外**：`#metricGrid mTumor` 这类"容器内 id"写法 CSS 选择器不好写，故 `LAYERS` 的注入函数支持两段式 selector（见 `injectTiers` 实现）。

### 11.10 `W` 权重与 `VL` 入场动画的接口（确认美术侧方案）

**确认采纳美术侧 v2.0 三套正交机制**：`Tier`（可见性，我）/ `W`（持久权重，他）/ `VL`（入场节奏，他）。

| 机制 | 归属 | 触发 | 作用 |
|---|---|---|---|
| `Tier` `T1/T2/T3` | **T1（本文档）** | 事件（完成 N 题 / 拖动 N 次） | 决定元素**在不在** |
| `W` `W1/W2/W3` | T2（美术侧） | **持续**（任何时刻都有效） | 决定元素**多亮**。关键作用：**T3 全可见时，L3 面板仍 `brightness(.78)`，培养皿永远是唯一亮块** |
| `VL` `VL1/VL2/VL3` | T2（美术侧） | 解锁那一帧，**一次性** | 决定**入场节奏** |

**我确认这三者不冲突，且解决了 v1.0 的模型缺陷**：美术侧原"纯时间窗"无法回答"T3 全解锁后靠什么维持焦点"；新增的 `W` 持续权重正是答案——**"可见" ≠ "同权重"**。

#### 11.10.1 接口方案确认（team-lead 要求确认）

✅ **确认：接口为纯 CSS 联动，T1 侧不新增任何 JS。**

```

                        ↓  CSS 自动响应
        ① 我的钩子：body.tier-N [data-tier="M"] { display:none }   → 可见性
```

## 14. 边缘情况（≥ 3 类）

1. **玩家在 L1 就把免疫拉到 100**：`pass()` 仍要求 `tumorPct<28 && malig<45`，免疫过高可能反把正常细胞也卷进去。→ L1 引导只提示"60 以上"，不鼓励拉满；若 200 轮内未达标，`finishMission(false)` 会给出「点『给点提示』看思路」，引导气泡追加一句「把免疫调回 60 左右再试一次」。
2. **玩家跳过 Step 1，直接点「给点提示」**：`btnHint` 在 L1 仍可用，`mission.hint` 会显示「免疫强度拉到 65 以上…」。→ 需把 `guard.hint` 的主标同步改写（`免疫兵力`/`含氧量`），否则提示里出现新玩家没见过的术语。**这是必须同步的一项。**
3. **玩家在 L1 反复重开（`btnReset`）**：L1 隐藏了重置按钮，但键盘快捷键 `R` 仍生效（L3492）。→ 需在 `keydown` 里加 `if (GS.tier===1) return;` 或把 `R` 也门控到 tier≥2。
4. **localStorage 里存了旧版本 / 损坏 JSON**：`JSON.parse` 抛错。→ `guideLoad()` 的 `try/catch` 已覆盖，返回 `null` 走默认值。
5. **玩家用专家模式进入 L3 后又想重看引导**：无入口。→ 提供"重置引导"：清 `vcl.guide.v1` 后刷新，或顶栏加长按 `⚙` 3 秒重置（低优先，可延后）。
6. **窗口宽度 < 1080px（源码已有媒体查询）**：右栏折到下方，"只留一根滑块"的视觉冲击下降。→ L1 的引导气泡文案本身已指示"把免疫兵力拖到 60 以上"，不依赖左右位置；可接受。
7. **`no_tumor` 里程碑需"曾有过肿瘤"**：L1 若玩家一直不开演化，不会有肿瘤。→ L1 开局自带 3 个肿瘤细胞（`guard` 场景本身就长肿瘤），不会触发该边界。
