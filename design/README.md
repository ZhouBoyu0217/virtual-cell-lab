## 一、这次要解决什么

用户原话：**"趣味性还可以高一点，并且上手难度要低一点"**。

主理人诊断结论：**这两个问题根因相同——复杂度没有分层。**

新玩家第一屏需面对 **40+ 个同权重元素**：
- 界面不是"控件太多"，而是**所有控件长得一样** —— 9 张 `.card` 全是 `#1a1c20` 面 + `#282b31` 边，彼此对比度 **1.000（完全相同）**，边框对卡面的可见度仅 **1.20（几乎隐形）**。
- 结果：玩家不知道该看哪里 → 不敢动手 → 体验退化成"看画" → 趣味性上不去。

**解法不是删功能，是建立可量化的视觉权重阶梯 + 按节奏释放复杂度。**

## 三、核心设计

### 3.1 三层边界（`Tier`，事件驱动，不由时间决定）

| 层 | 屏幕上剩什么 | 可操作控件 | 跃迁条件 |
|---|---|---|---|
| **Tier 1 · 30秒上手** | 培养皿 + 旁白条 + 引导气泡 + 精简任务卡 + **唯一指标** + **唯一滑块** + 播放按钮 | **3** | 完成第 1 题 **或**（碰过 ≥5 个控件 且 ≥60 回合） |
| **Tier 2 · 探索** | 分批释放：因子 1→3→5、工具 0→1→2→3、曲线、局势、收集板 | ≤ 14 | 完成第 3 题 **或** 碰过 ≥5 个控件 |
| **Tier 3 · 精通** | 全量 | 29 | — |

> **关键**：`Tier` 只决定「**是否可见**」。元素「**多醒目**」由美术侧 `W1/W2/W3`（持久权重）独立控制，即使 Tier 3 全解锁，次要面板仍长期压暗，培养皿始终是全屏唯一亮块。核心洞察：**"可见 ≠ 同权重"**。

### 3.2 Tier 1 三步引导（逐字）

| 步骤 | 玩家看到 | 玩家动作 | 得到什么 |
|---|---|---|---|
| **Step 0** | 旁白"这盘细胞里混进了 3 个坏细胞…" + 气泡"先点这个按钮▶" | 点「开始」 | 3 个肿瘤细胞红色描边高亮 |
| **Step 1** | 气泡"把『免疫兵力』拖到 60 以上试试" | 拖唯一滑块 | 培养皿立刻长出绿色免疫细胞（可见实体） |
| **Step 2** | 跑满 200 回合 | — | "✓ 你赢下了第一局。**这不是运气** —— 免疫压力真的把肿瘤压住了" |

> **设计精髓：首战保底成功。** 第 1 题的预设免疫值已是 62，玩家只推一根滑块就能达标。把随机数值**归因到玩家自己的操作**，这是胜任感（SDT）的锚点。

### 3.3 术语通俗化（14 组，全量替换含旁白）

| 原术语 | 人话 | 源码可见处 |
|---|---|---|
| 肿瘤占比 | **坏细胞比例** | — |
| 恶性度 | **危险度**（低/中/高三色带，阈值 40/70） | 3 |
| 汇合度 | **铺满度** | 1 |
| 免疫强度 | **免疫兵力** | 4 |
| 氧气浓度 | **含氧量** | 3 |
| 突变率 | **变异速度** | 4 |
| 化疗药剂 | **化疗药量** | 3 |
| 营养供给 | **养分** | 3 |
| 溶瘤病毒 | **病毒剂量** | 13 |
| 命运判定 | **培养皿局势** | — |
| 实验记录 | **发现记录** | — |

> **实施方式**：**原地改字符串字面量**，不遍历 DOM。原因：`index.html:2196` 的「恶性度」是**运行时字符串拼接**（`'">恶性度 ' + M.malig`），DOM 替换**必然漏掉**。
> **绝不可动**：`M.tumorPct/confluence/malig/total`（`probe/pass` 判据直接用）、`E.*`（内核按键读 id 非 label）、`type:'tumor'`、`data-env="immune"`、`MISSIONS[].id`。

### 3.4 趣味性手法（本期 5 条）

| # | 手法 | 做什么 → 得到什么 |
|---|---|---|
| 1 | 变化即台词 | 拖滑块 1.5s 内回一句因子专属因果旁白（12 条文案已写） |
| 2 | 首次裂解定格 | 0.6s 慢动作 + 冲击环（稀缺性记忆点） |
| 3 | 幽灵轨迹 | 曲线上叠上一次的灰虚线 → 重试变成自我比较 |
| 4 | 压力可视化 | 细胞数 < 40 时视野边缘红色呼吸暗角（最大不透明度 0.22） |
| 5 | 解锁即奖励 | 新面板滑入动画 + tier 徽章，把"负担"变"战利品" |

> 手法 6「预测-验证小赌注」**已延后**，本期不实现。

### 3.5 专家模式（逃生通道）

顶栏常驻 `⚙ 专家模式` 按钮，**从 Tier 1 第一屏就可见** —— 老玩家不必先受引导折磨。点击即 `tier=3`，可逆，不丢已解锁内容。

**存储降级规格**：单键 `vcl.guide.v1`，强制 `try/catch`。
> 读不到存档 → 引导从头走一遍；写不进存档 → 静默忽略。**全程不报错、不白屏、不弹提示。**

> ⚠️ **这是本次唯一致命风险**：源码是**单个 IIFE**（`index.html:385`），任何未捕获异常都会终止整个初始化 → `boot()` 不执行 → 加载遮罩永不隐藏 → 玩家看到**永久转圈**。

## 四、源头实现要点（交工程侧）

### 4.1 单一事实来源：`LAYERS` 常量

```js
/* 值 = 该元素从第几层开始可见 */
var LAYERS = {
  '#dish': 1, '#hud': 1, '#evt': 1, '#hint2': 1, '#missionCard': 1,
  '#metricGrid mTumor': 1, '[data-env="immune"]': 1,
  '#btnPlay': 1, '#btnHint': 1, '#btnExpert': 1, '#tierBadge': 1,
  '[data-env="nutrient"]': 2, '[data-env="oxygen"]': 2,
  '[data-tool="inspect"]': 2, '#chartCard': 2, '#fateCard': 2,
  '#inspCard': 2, '#metricGrid mConf': 2,
  '#mileCard': 2, '#metricGrid mMalig': 2, '#riskBand': 2,
  /* ...完整表见 GDD §11.9 */
};
```

流程：`boot() → injectTiers() → applyTier() → CSS 执行`
- `LAYERS` = **唯一真值**，改边界只改这一处
- `data-tier` = **派生注入**，人不手写（40+ 处手写任一处笔误都难发现）
- CSS 只认 `data-tier` 属性，**一行不用改**

### 4.2 实施顺序（**必须按序**）

| 步骤 | 内容 | 风险 |
|---|---|---|
| **1–4** | 纯视觉降噪（配色阶梯、锁壳、焦点手法、动效参数） | **零风险**，不动结构 |
| 5–8 | 引入解锁机制（`LAYERS` 注入、`applyTier`、状态机） | 中 |
| 9 | 接口对接：`applyTier()` 切 `body.className` → 美术侧 W 权重选择器自动生效（**无需新增 JS**） | 低 |

> 建议步骤 1–4 先落地确认观感，再做 5–9。这样即使边界有变，降噪收益已到手。

### 4.3 两个易错实现细节（设计侧明确警告）

**① `#btnExpert` 改色时，必须保留 `class="ubtn"`**

```css
/* 正确：保留 class 以复用布局（padding / cursor / transition），仅覆盖 color */
#btnExpert { color: #8b8e97; }        /* 4.62 ✓ AA */
#btnExpert:hover { color: #d6d8de; }
```

> ⚠️ 若为了改色而**去掉 `ubtn` class**，会连带丢掉布局样式，导致按钮错位。原 `.ubtn{color:#7c7f88}` 实测对比度 3.83，**不过正文 AA**（需 4.5）。

**② 术语改写必须原地改字符串字面量，不能遍历 DOM**

`index.html:2196` 的「恶性度」是**运行时字符串拼接**：`'">恶性度 ' + M.malig + '</span>'`。
DOM 遍历替换**必然漏掉这一处**（它在运行时才组装，初始 DOM 里不存在）。原地改还附带两个好处：零运行时开销、可被 Grep 验收。

| 门 | 判定 | 关键发现 |

### 本轮抓到的 4 个真缺陷

| # | 缺陷 | 严重度 |
|---|---|---|
| **Bug-1** | `distinctSliders()>=3` 是**死条件** —— Tier 1 只暴露 1 根滑块，玩家永远无法通过这条路跃迁 | **高**（引导卡死） |
| **Bug-2** | `distinctSliders()>=6` 同样不可达 —— 「变异速度」刻意留到 Tier 3，Tier 2 最多碰 5 根 | **高** |
| Bug-3 | Tier 2 控件上限"≤12"漏算化疗/病毒滑块（真实上限 14） | 中 |
| Bug-4 | `#btnPlay` 两套动画互相覆盖 | 中 |

> Bug-1/2 是**交叉检查逼出来的**：主理人追问"Tier 2 到几个控件"→ 迫使去数滑块 → 才发现死条件。

### 一次高质量的专业对撞（记录在案）

**美术侧 v1.0** 把三道层定义为**时间窗**（0–1s 显示一层，>3s 全显示）。
**策划侧反驳**：若 3 秒后全显示，玩家开门 3 秒后依然面对 40+ 控件 —— **等于什么都没修**。
**美术侧接受并整篇重写**，拆成三套正交机制（可见性 / 持久权重 / 入场节奏），核心洞察：**"可见 ≠ 同权重"**。
