## 0. 一句话结论

**当前界面不是"控件太多"，而是"所有控件长得一样"。** 9 个 `.card` 共用同一个卡面 `#1a1c20`、同一个边框 `#282b31`、同一档字号、同一明度 —— 彼此对比度 **1.000（完全相同）**，边框对卡面的可见度仅 **1.20（几乎隐形）**。视觉上没有任何一个元素有资格说"先看我"。降噪的正确做法不是删控件，而是**建立一条可量化的视觉权重阶梯**，让"看哪里"由设计决定，而不是由玩家的随机扫视决定。

## 1. 实测诊断（基于真实代码与首屏截图，非推测）

### 1.1 控件口径（与文策渊统一 · 双口径并列）

**主理人指出我数与文策渊数不一致** —— 两个口径都成立，但**基数不同**。此处明文定义，避免汇编时看似矛盾：

| 口径 | 定义 | 数值 | 谁用 |
|---|---|---|---|
| **口径 A · 功能单元** | 玩家能**点 / 拖 / 读**的离散功能元素，去重 | **43** | 文策渊 —— **功能门控**依据（只有功能单元需要按层释放） |
| **口径 B · DOM 可视块** | 口径 A ＋ 5 个纯展示容器（`header` / `.dishwrap` / `#legend` / 曲线 canvas / 放大 canvas） | **48** | 本方案 —— **视觉权重**计算依据（亮块与面积直接受容器影响） |

- **本方案默认口径为 B（48）**，凡出现"视觉块 / 注意力竞争者"均指口径 B。
- 引用文策渊的功能门控时用口径 A（43）。
- 我逐个 Read 源码核对：14 静态 `<button>` + 8 预设（JS 生成）+ 7 `<input type=range>` + 6 指标块 = **35 交互控件**（33 首屏可见），叠加容器块后与口径 B 自洽。
- **两数不矛盾，且结论一致**：无论口径 A 还是 B，首屏同权重视觉块都 ≥40，根因都是"共享同一套视觉常量"。

### 1.2 三个真正的病灶

**病灶 A —— 单一表面（最致命）**
9 个 `.card` 全是 `background:#1a1c20;border:1px solid #282b31;border-radius:12px;padding:14px`。相对亮度全部 Y=0.01154，**彼此对比度 1.000**。边框 `#282b31` 对卡面可见度仅 **1.20**，卡片糊成一整片"卡片墙"。

**病灶 B —— 单一文字档位**
`#e6e6ea`（主）/ `#9295a0`（次）/ `#6f727a`（弱）三档挤在同一 `11–13px` 区间。弱化色 `#6f727a` 在卡面上仅 **3.55**，既不够弱到"退后"，也不够亮到"可读"——卡在最坏的中间地带。

**病灶 C —— 两个"亮块噪声源"（实测确认）**
1. **放大观察画布**：`drawInspector()`（L2450）在**未选中细胞时**仍铺满 `radial-gradient(#d6d2ce → #c4c0bb)` 的近白米色。300×300 的亮块，**全屏最亮、零信息**。
2. **曲线图画布**：底色 `#16181b`，820×118 大面积块，同样抢焦。

**病灶 D —— 主角的焦点未被保护**
培养皿是首屏唯一有价值的视觉主角（相衬显微镜暖米白视野），却与四周同色卡片挤在一起，没有独占优势。

### 1.3 保留清单（本方案不触碰）

| 资产 | 位置 | 处理 |
|---|---|---|
| `phaseContrast()` 相衬成像管线 | L807 | **不动**（光程差 → 亮度差 + 边缘光晕，项目灵魂） |
| `PHASE_OPTS` 光学厚度参数 | L888 | **不动** |
| `OUTLINE_COLORS` 类型描边 6 色 | L900 | **不动**（画布内） |
| `VIRUS_TINT` 病毒青蓝 | L910 | **不动** |
| 培养皿底色 `#0d0e10` | L45 | **不动** |
| `DEAD_BODY` / `CELL_LOOK` 等渲染参数 | L896+ | **不动** |

> **边界纪律**：本方案**全部配色改动只作用于 HTML/CSS 的 UI chrome**。§8.6 的「类型色修正」**仅用于 HTML 文字**（图例、指标数字、徽记），**绝不复用于画布描边**。`OUTLINE_COLORS` 与 `PHASE_OPTS` 保持原值。

## 2. 模型对齐与主理人裁决（v3.0 核心修订）

> 本节记录两轮修订：**文策渊的模型纠正**（§2.1–2.2）与**主理人的权威裁决**（§2.3–2.5）。**这是 v3.0 最重要的一节，请优先阅读。**

### 2.1 命名解冲突（采纳文策渊建议）

v1.0 用 `L1/L2/L3` 指代**视觉层**，与文策渊的**引导层级** `L1/L2/L3` 撞车。**v3.0 起统一命名**（见文首术语约定）：

| 概念 | 归属 | 命名 | 含义 |
|---|---|---|---|
| 解锁层级 | 文策渊 | **`Tier 1 / Tier 2 / Tier 3`** | **事件驱动**的进度门控，决定元素**是否可见** |
| 视觉权重层 | 本方案 | **`W1 / W2 / W3`**（Weight） | **持久**的注意力权重，决定元素**多醒目** |
| 入场动画节奏 | 本方案 | **`VL1 / VL2 / VL3`**（Visual Layer） | **一次性**的揭示节奏，决定元素**怎么出现** |

### 2.2 关键纠正：可见性靠事件门控，动画节奏才靠时间窗（采纳文策渊 §11.7.2）

**文策渊的批评成立，v1.0 的模型有根本缺陷。**

v1.0 把 `VL1=0–1s / VL2=1–3s / VL3=>3s` 当作**元素可见性**的时间窗 —— 那么玩家开门 3 秒后**依然面对 43 个控件**，等于什么都没修（复杂度只是被延后 3 秒，没有被分层）。

**v3.0 改为「可见性」与「节奏」正交的两套机制：**

| 维度 | 归属 | 规则 |
|---|---|---|
| **元素是否可见** | 文策渊 | 由 `GS.tier` + `data-tier` 决定，**事件驱动**（完成 N 题 / 碰过 N 根滑块）。**不由时间决定。** |
| **元素多醒目（持久）** | 本方案 · **W1/W2/W3** | 与 Tier **同步**但**独立于动画**：任何时刻都有权重阶梯，**即便 Tier 3 全部可见时，培养皿仍是唯一主角** |
| **元素怎么出现（一次性）** | 本方案 · **VL1/VL2/VL3** | **只在解锁那一帧触发一次**的三级入场节奏 |

> **这个修订解决了 v1.0 没有回答的问题：Tier 3 全解锁之后靠什么维持焦点？**
> 答案：**持久权重（W）**。Tier 3 时所有面板都可见，但 W3 面板仍长期处于 `brightness(.78)`，培养皿（W1）依然是全屏唯一亮块。**"可见" ≠ "同权重"。**

## 3. 视觉层级重建（W1/W2/W3 权重阶梯）

### 3.1 三层定义

| 层 | 名称 | 视觉角色 | 权重预算 | 典型元素 |
|---|---|---|---|---|
| **W1** | 焦点层 | **主角 + 当前唯一 CTA**。最高明度、唯一强边框、唯一动效 | **58%** | dish、精简任务卡、`#btnPlay` |
| **W2** | 支撑层 | **本层会用到的工具与反馈**。正常明度、中性边框、无动效 | **32%** | 旁白、气泡、HUD、唯一杠杆、核心指标、曲线、工具与播放控制 |
| **W3** | 后置层 | **进阶参数**。下沉明度、隐形边框 | **10%** | 其余滑块、8 预设、局势、放大观察、记录、速度 |

### 3.2 核心机制：权重随 Tier 迁移

**同一个元素在不同 Tier 下权重不同** —— 这是"分层释放"在视觉上的落点。例：`immune` 滑块在 **Tier 1 是唯一杠杆（W2）**，到 **Tier 3** 与另 5 根并列时降为 **W3**。

实现方式：CSS 用 `body.tier-N` 与元素 class 组合选择器，**不改 DOM 结构**。

```css
/* 权重基准（按元素角色定，不随 Tier 变） */
.w-dish{ --w:1; }  .w-mission{ --w:1; }  .w-play{ --w:1; }
.w-rail{ --w:2; }  /* 旁白/气泡/HUD/唯一杠杆/工具/曲线 */
.w-core{ --w:2; }  /* 核心指标 */
.w-panel{ --w:3; } /* 后置面板 */

/* Tier 迁移：Tier 1 的"唯一杠杆"到 Tier 3 降权（与另 5 根并列） */
body.tier-1 .w-rail, body.tier-2 .w-rail{ --w:2; }
body.tier-3 .w-rail{ --w:3; }
```

### 3.3 「至少一个 CTA」规则

| **Tier 2** | `#btnPlay` + `#btnHint`（提示） | 玩家已会操作，CTA 转为"求助" |
| **Tier 3** | `#btnPlay` | 全面板下保持单一启动点 |

| `⚙ 专家模式`（新增） | `w-escape` | W3 | W3 | W3 | 逃生阀，**刻意低权重不抢焦** |

> **合并冗余**：顶栏 `.hint` + `#hint2` + `#toolTip` 三处都在说"点击细胞可放大"，**合并为引导气泡一句**（走 `#evt` + `#hint2`），其余删除。

**结果：Tier 1 首屏注意力竞争者从 48（口径 B）→ 9 个视觉块，其中 W1 仅 3 个（口径 B 下视觉块 ≤6）。**

### 3.5 权重预算与验收

| 层 | 目标注意力占比 | 明度处理 |
|---|---|---|
| W1 | **58%** | `brightness(1)` + 外发光 + `scale(1.012)` + 脉冲 |
| W2 | **32%** | `brightness(1)`，无动效 |
| W3 | **10%** | `brightness(.78) saturate(.85)` |

> **验收方法**：把首屏转灰度图，估算「最亮 3 个区域的亮度总和 ÷ 全页亮度总和」应 **≥0.5**。当前实测约 0.28（放大观察画布、曲线图、培养皿三者互争）。改造后应只剩培养皿一个亮块。

#### 3.5.1 `Tier 1` 唯一杠杆的视觉核心（按主理人 A3 裁决重点处理）

主理人明确要求：**"Tier 1 的单滑块是'唯一杠杆'的视觉核心，请重点给它最高的视觉权重"**。

**设计难点**：它必须**足够醒目**（Tier 1 唯一可操作物），但**不能升到 W1** —— 否则 Tier 1 会出现第 4 个亮点（canvas + 任务卡 + 开始键 + 杠杆），破坏"培养皿是唯一主角"。

**解法：把它做成「W2 中的最高档」—— 用内部强调而非外层抬权。** 不改卡面明度、不加外发光，只在**卡内**做三处强调：

| 手段 | 规格 | 实测对比度 |
|---|---|---|
| **① 轨道填充色**（普通滑块轨道 `#31343b`） | 轨道改为 `#7ddba8`（强调绿） | 与普通轨道对比 **7.46** —— 一眼看出"这根不一样" |
| **② 标签文字** | 标签用主文字 `#e6e6ea`（其余滑块用 `#9295a0`） | 13.71 vs 5.71 —— 明确的主次 |
| **③ 滑块拇指放大** | 拇指直径 `15px → 19px`，加 `box-shadow:0 0 0 3px rgba(125,219,168,.22)` 光环 | 尺寸 + 光环双通道 |
| **④（可选）微脉冲** | 轨道 `box-shadow` 呼吸 3200ms（比 CTA 脉搏更慢更低频） | 作为"唯一杠杆"的温和提示 |

```css
/* Tier 1 唯一杠杆：W2 内最高档，不升 W1 */
body.tier-1 .w-rail.lever{ --w:2; }
body.tier-1 .lever input[type=range]{ background:#7ddba8; }        /* 轨道强调 */
body.tier-1 .lever input[type=range]::-webkit-slider-thumb{
  width:19px; height:19px; background:#e8fbf1;
  box-shadow:0 0 0 3px rgba(125,219,168,.22), 0 1px 3px rgba(0,0,0,.4);
}
body.tier-1 .lever .row span{ color:var(--t-hi); }                 /* 标签提亮 */
```

> **验收**：Tier 1 灰度化后，杠杆卡**不应**进入"最亮 3 区域"（保持 1 亮点 + 1 暖点 + 1 绿条的结构），但**彩色视图下**它因绿色轨道成为**右栏唯一的颜色锚点** —— 这正是"唯一杠杆"要的：不是更亮，而是**唯一有颜色**。

## 4. 未解锁控件的视觉处理（3 方案 + 明确推荐）

> ✅ **文策渊已采纳本方案并补充了完整文案表**（`onboarding-design.md` §11.3.5），其中 14 个锁态元素的解锁条件文案（统一三种句式：`完成 N 次实验后解锁` / `开始第一次实验后解锁` / `进入精通后解锁`）**可直接使用**。v1.0 的 A5 依赖已解除。

### 方案 A — 完全隐藏（`display:none`）

| 维度 | 评估 |
|---|---|
| 优点 | 首屏最干净，注意力 100% 集中在 W1 |
| **致命缺点** | **玩家不知道功能存在**，无法形成"还有内容"的预期，也没有解锁动力 |
| 布局副作用 | 解锁瞬间**发生 reflow**，下方内容整块位移，玩家"界面跳了一下"而丢失焦点 |
| 适用 | 仅适合**体量过大的容器**（见下方例外）或 debug 元素 |

### 方案 B — 降透明度（保留原位，`opacity:.42` + `disabled`）

| 维度 | 评估 |
|---|---|
| 优点 | 零布局跳动；保留"有东西"的感知 |
| **致命缺点** | 现有 `button:disabled{opacity:.42}`。**实测：文字 `#e6e6ea` 叠 `opacity:.42` 后等效 `#75777c` on `#1e2125` → 对比度仅 3.61，低于 WCAG AA 正文 4.5。** |
| 认知副作用 | 大片半透明控件仍占面积，玩家会持续尝试点击并被拒绝 |
| 适用 | 只用于**短暂过渡态**（点击到生效之间） |

### 方案 C — 占位骨架（shimmer 骨架屏）

| 维度 | 评估 |
|---|---|
| **缺点** | 骨架屏是**加载语义**。用于"未解锁"会让玩家以为页面正在加载/卡住 → **焦虑与等待感** |
| 实现成本 | 每个控件需额外骨架 DOM，与动态生成的滑块/预设难复用同一套 CSS |

### ✅ 推荐方案：D — **锁壳（Locked Shell）**

**保留卡片外壳，卡内控件进入低权重禁用态，右上角加一枚可读的锁徽记。**

| 特征 | 规格 |
|---|---|
| 卡片外壳 | **保留**：`background:#16181b; border:1px solid #202329; border-radius:11px` |
| 卡片标题 | **保留可见**：`12.5px / 400 / #8b8e97`（对比度 5.43 ✓AA） |
| 卡内控件 | `.lockbody{opacity:.5; filter:grayscale(.35); pointer-events:none}` |
| 锁徽记 | 右上角胶囊 `🔒 完成 1 次实验后解锁`，`11px / #8b8e97 on #202329`（4.81 ✓AA） |
| 布局 | **占位与原尺寸一致** → 解锁时**零 reflow** |

**为什么推荐它（四条理由）：**
1. **布局零跳动** —— 解锁时控件原地"点亮"，不 reflow，玩家不丢焦点。三个方案里**唯一**做到。
2. **对比度合规** —— 锁条件 5.43、徽记 4.81，均过 AA。方案 B 原实现只有 3.61。
3. **好奇心而非焦虑** —— 有标题 + 有解锁条件 → "这里有功能，达到 X 就能用"（正向预期）；不像骨架传达"加载中"，也不像隐藏传达"没有这东西"。
4. **有解锁动机** —— 解锁条件明文 = 把 Tier 3 的目标**前置**，直接为三层引导提供钩子。

#### ⚠️ 例外：`#inspCard` 不适用锁壳

文策渊指出（我同意）：**`#inspCard` 在 Tier 1 应完全不渲染（`display:none`，连锁壳都不给）**。理由：

1. 它面积约 300×300，**即使低亮度锁壳也占右栏近一半** —— 锁壳的"保留存在感"对它是负收益。
2. 它的功能依赖 `点选观察` 工具，而该工具 Tier 2a 才解锁 —— Tier 1 显示一个用不了的放大面板是纯干扰。
3. 它属"深化认知"而非"建立信心"，研究动机应在 Tier 2。

> **锁壳适用边界**：**体量小的卡片（滑块卡 / 预设卡 / 记录卡 / 曲线卡 / 局势卡）用锁壳；体量大的容器（`#inspCard`）直接隐藏。**

```css
/* ---- 锁壳（可直接粘贴） ---- */
.card.locked{
  position:relative;
  background:#16181b; border-color:#202329; border-radius:11px;
  filter:brightness(.62) saturate(.8);
}
/* 锁条件徽记：不被父级 filter 二次压暗，独立抬亮 */
.card.locked .lockchip{
  position:absolute; top:9px; right:9px; z-index:2;
  display:inline-flex; align-items:center; gap:5px;
  font-size:11px; line-height:1; color:#8b8e97;
  background:#242830; border:1px solid #2f343d; border-radius:999px;
  padding:4px 9px; white-space:nowrap;
  filter:brightness(1.61);           /* 抵消父级 .62，回到满明度 */
}
.card.locked .lockbody{ opacity:.5; filter:grayscale(.35); pointer-events:none; }
.card.locked button, .card.locked input{ pointer-events:none; }
.card.locked [aria-hidden="true"]{ user-select:none; }
```

> **注意**：`#inspCard` 在 Tier 1 用 `display:none` 而**不加 `.locked`** —— 由 `data-tier` 门控负责（`body.tier-1 [data-tier="2"]{display:none}`）。

主理人裁决门槛 + 文策渊 `§11.3.5` 的卡级文案，**本方案采用卡级（更具体）**：

## 5. 引导焦点手法（具体 CSS / Canvas 参数）

四种手法**叠加**使用，全部通过 `filter` / `box-shadow` / `transform` 实现，**不改任何文字颜色**，因此不损害对比度。

### 5.1 降低非焦点区域对比度（主力手法）

原理：人眼被**绝对亮度**牵引。把非焦点区域压暗，它们就"沉进页面"，焦点自然浮起。

```css
/* 各层用自定义属性声明自己的明度档，保证"单条 filter"不叠加冲突 */
.card{ filter: brightness(var(--w-b,1)) saturate(var(--w-s,1)); }
.card.w-panel{ --w-b:.78; --w-s:.85; }        /* W3 常态下沉 */
.card.locked { --w-b:.62; --w-s:.8;  }

/* 引导聚焦模式：W2/W3 在自身档位上再乘系数（仍是单条 filter） */
.shell.focusing .card{ --w-b:calc(var(--w-b,.78) * .72); --w-s:.9; }
.shell.focusing .card.w-mission,
.shell.focusing .card.w-dish{ --w-b:1; }

.card{ transition: filter 600ms cubic-bezier(.4,0,.2,1); }
```

**实测校验**：`brightness(.72)` 施加于 W2 卡后，文字 `#e6e6ea` → 等效 `#a5a5a8` on `#131416` = **对比度 7.17**（原 13.71）。**仍远超 AA 4.5** —— 压暗了，但**依然读得清**，这正是要的"退后但不消失"。

> 时长 **600ms** + `cubic-bezier(.4,0,.2,1)`（对称缓入缓出）：足够慢，让玩家感到"世界安静下来了"，而不是"闪了一下"。

### 5.2 显微镜聚光（dish 周边压暗 —— 保护主角）

给 W1 主角一圈向内衰减的暗角。**纯 CSS，无需改 Canvas：**

```css
.dishwrap{ position:relative; }
.dishwrap::after{
  content:""; position:absolute; inset:0; pointer-events:none; border-radius:11px;
  background: radial-gradient(ellipse 78% 84% at 50% 46%,
              rgba(13,14,16,0) 58%, rgba(13,14,16,.34) 84%, rgba(13,14,16,.62) 100%);
  opacity:.85; transition: opacity 600ms cubic-bezier(.4,0,.2,1);
}
.shell.focusing .dishwrap::after{ opacity:1; }
```

> 用 `rgba(13,14,16,·)`（= 皿底色 `#0d0e10`）而非纯黑，保证暗角与皿内视野同色系不色偏。最大不透明度 **0.62**，**绝不破坏相衬液泡质感** —— 只在边缘轻微收暗。

### 5.3 外发光 + 轻微缩放（W1 焦点卡）

```css
.card.w-mission{
  border-color:#3f7d5f;
  box-shadow:
    0 0 0 1px rgba(77,154,114,.35),      /* 内圈实描边，强化边界 */
    0 0 22px rgba(125,219,168,.14),      /* 外发光，"通电"感 */
    0 6px 20px rgba(0,0,0,.35);          /* 落地阴影，制造浮起 */
  transform: scale(1.012) translateZ(0);
  transform-origin: 50% 50%;
  z-index: 2;
  transition:
    transform   320ms cubic-bezier(.22,1,.36,1),
    box-shadow  320ms cubic-bezier(.22,1,.36,1),
    border-color 320ms ease;
  will-change: transform;
}
```

> `scale(1.012)` 极轻 —— 1.2% 刚好越过"可察觉"阈值又不产生模糊。配 320ms `cubic-bezier(.22,1,.36,1)`（强 ease-out），产生"被轻轻推向前"的手感。`translateZ(0)` 强制 GPU 合成层，避免 scale 引起文字重绘抖动。

**发光强度可辨性校验**（避免被相邻卡片吃掉）：
| α | 等效色 | vs 页底 | vs W2 卡面 |
|---|---|---|---|
| 0.14（推荐） | `#263831` | 1.48 | 1.37 |
| 0.22 | `#314c40` | 1.96 | 1.82 |
| 0.35 | `#436e58` | 3.17 | 2.93 |

推荐 **0.14–0.22**：足以察觉，又不至于变成"发光绿方块"抢走培养皿的主角地位。

### 5.4 脉冲动画（仅用于"现在该点这里"的 CTA）

**全局同时最多一处脉冲。** 多处脉冲 = 无脉冲。

```css
@keyframes focusPulse{
  0%,100%{ box-shadow:
      0 0 0 1px rgba(77,154,114,.35),
      0 0 18px rgba(125,219,168,.10),
      0 6px 20px rgba(0,0,0,.35); }
  50%    { box-shadow:
      0 0 0 1px rgba(77,154,114,.60),
      0 0 34px rgba(125,219,168,.26),
      0 6px 20px rgba(0,0,0,.35); }
}
.w1-cta{ animation: focusPulse 2400ms cubic-bezier(.4,0,.2,1) infinite; }
/* 玩家一旦交互，脉冲立即停止（避免长期闪烁干扰） */
.shell.interacted .w1-cta{ animation:none; }
```

> **2400ms** 周期：比心跳慢、比呼吸快，落在"平静但活着"的区间。低于 1500ms 显得焦躁，高于 3000ms 被忽略。
> 缓动用 `cubic-bezier(.4,0,.2,1)` 而非 linear —— 对称缓入缓出，避免"频闪"。
> ⚠️ **与文策渊 §11.2 `breathe` 的整合**：文策渊的 `body.tier-1 #btnPlay{animation:breathe 1.8s}` 是同一意图的轻量版。**建议二选一** —— 采纳本节的 `focusPulse`（2400ms，有内圈描边与外发光双层，且交互即停），删除文策渊的 `breathe` 以避免两条动画争抢同一元素。已知会文策渊。

### 5.5 Canvas 侧焦点手法（选中细胞时的聚光）

玩家点选细胞后，**在 Canvas 内**把视线锁到该细胞。纯绘制，一次性开销，`phaseContrast` 不受影响：

```js
/* 在 dish 绘制流程末尾追加：选中细胞时压暗周边（暗角随细胞位置移动） */
function drawPickFocus(ctx, cell, W, H){
  if (!cell) return;
  var R = 210;                                  /* 亮区半径 px */
  var g = ctx.createRadialGradient(cell.px, cell.py, 0, cell.px, cell.py, R);
  g.addColorStop(0.00, 'rgba(13,14,16,0)');
  g.addColorStop(0.50, 'rgba(13,14,16,0.10)');
  g.addColorStop(0.78, 'rgba(13,14,16,0.34)');
  g.addColorStop(1.00, 'rgba(13,14,16,0.66)');
  ctx.fillStyle = g;
  ctx.fillRect(0, 0, W, H);
}
```

> 最大压暗 **0.66**，与 CSS 暗角同值 —— 保证**边缘细胞仍隐约可见**（玩家不会觉得视野被裁掉），但注意力已拉回被选中的那个。
> 若用 `0.9+` 会变成"只看得见一个细胞"，丢掉培养皿整体感，**不建议**。
> 半径 `210px`：dish 为 820×690，210 ≈ 单细胞直径的 8–12 倍，形成"细胞 + 邻居"的语境而不孤立。

**配套：选中细胞的呼吸环**（温和一圈脉冲，强化"就是它"）：

```js
var phase = (performance.now() % 2000) / 2000;          /* 0→1 */
var pulse = 0.5 - 0.5 * Math.cos(phase * Math.PI * 2);   /* 0→1→0 平滑 */
var ringR = cell.r * (1.24 + 0.10 * pulse);
ctx.beginPath();
ctx.arc(cell.px, cell.py, ringR, 0, Math.PI * 2);
ctx.strokeStyle = 'rgba(125,219,168,' + (0.30 + 0.30 * pulse).toFixed(3) + ')';
ctx.lineWidth = 2;
ctx.stroke();
```

> 用 `cos` 而非三角波，得到正弦般平滑的呼吸感，周期 **2000ms**。环色为强调绿 `#7ddba8` 的 rgba 形式，**不改细胞任何描边色**。

### 5.6 压力可视化（与文策渊手法 4 对接）

文策渊 §8 手法 4 提出"濒临崩溃时视野边缘泛红脉冲"。**我提供可访问性合格的具体色值**（避免纯红闪烁触发不适）：

```js
/* 文策渊 §8 手法 4 的实现参数（我补充色值与参数） */
var danger = (M.total < 40 || M.malig > 70);
if (danger) {
  var p = 0.5 - 0.5 * Math.cos((performance.now() % 1200) / 1200 * Math.PI * 2);
  var g = ctx.createRadialGradient(W/2, H/2, Math.min(W,H)*0.32,
                                   W/2, H/2, Math.max(W,H)*0.62);
  g.addColorStop(0, 'rgba(206,72,60,0)');
  g.addColorStop(1, 'rgba(206,72,60,' + (0.10 + 0.12 * p).toFixed(3) + ')');
  ctx.fillStyle = g; ctx.fillRect(0, 0, W, H);
}
```
> 用类型描边同源的肿瘤红 `rgba(206,72,60,·)`，**最大不透明度仅 0.22**（文策渊原案未定值）—— 保证是"氛围紧张"而非"红色警报闪烁"。周期 **1200ms** 与文策渊一致。
> ⚠️ **reduced-motion 下保留此效果但去掉呼吸**（固定 `p=0.5`），因为它承载的是**信息**（局势恶化）而非装饰 —— 与文策渊 §11.7.4 "裂解定格保留" 同一原则。

## 6. 三层解锁的过渡动效设计（VL1/VL2/VL3）

> **与文策渊的整合关系**：文策渊 §11.2 提供了基础钩子 `@keyframes unlockIn{from{opacity:0;transform:translateY(-8px)}}` + `.card[data-tier]{animation:unlockIn .22s ease}`。**本节是它的强化与结构化版本** —— 文策渊的 `.22s` 适合"低权重元素低调出现"，本节补充**解锁整层时的仪式感节奏**。**两者不是两套系统，而是同一系统的两档**（见 §6.5 选择表）。

**核心思路**：解锁不是"状态切换"，而是**奖励事件**。动效要有明确时间结构：预备 → 揭示 → 光扫 → 落定。

### 6.1 单元素揭示

| 阶段 | 时间 | 属性 | 曲线 |
|---|---|---|---|
| a. 预备 | 0ms | `opacity:0; transform:translateY(8px) scale(.98)` | — |
| b. 揭示 | 0 → 420ms | `opacity:0→1; translateY→0; scale→1` | `cubic-bezier(.22,1,.36,1)` |
| c. 光扫 | +120 → +840ms | 伪元素高光从左至右扫过 | `cubic-bezier(.4,0,.2,1)` |
| d. 落定 | 420ms | 完成态 | — |

```css
@keyframes revealUp{
  0%   { opacity:0; transform:var(--rv-from, translateY(8px)) scale(.98); }
  100% { opacity:1; transform:translateY(0) scale(1); }
}
@keyframes sweepLight{
  0%   { transform:translateX(-120%); opacity:0; }
  18%  { opacity:.9; }
  100% { transform:translateX(120%);  opacity:0; }
}
.reveal{
  animation: revealUp 420ms cubic-bezier(.22,1,.36,1) both;
  animation-delay: var(--rv-delay, 0ms);
  position: relative; overflow: hidden;
}
.reveal::after{
  content:""; position:absolute; inset:0; pointer-events:none;
  background:linear-gradient(105deg,
      rgba(125,219,168,0) 30%, rgba(125,219,168,.16) 50%, rgba(125,219,168,0) 70%);
  transform:translateX(-120%);
  animation: sweepLight 720ms cubic-bezier(.4,0,.2,1) both;
  animation-delay: calc(var(--rv-delay, 0ms) + 120ms);
}
```

### 6.2 卡级揭示

```css
@keyframes revealCard{
  0%   { opacity:0; transform:translateY(10px); }
  70%  { opacity:1; transform:translateY(0); }
  85%  { transform:scale(1.006); }
  100% { transform:scale(1); }
}
.card.reveal-card{ animation: revealCard 480ms cubic-bezier(.22,1,.36,1) both; }
```

> 85% 处一个 **`scale(1.006)`** 微弹（0.6%），制造"弹了一下"的落定手感。幅度必须极小，否则廉价。

### 6.3 VL1/VL2/VL3 —— 一次解锁事件内的三级节奏

这是 文策渊 §11.7.2 要求的重定义：**VL 不是游戏开局的时间窗，而是"解锁那一帧"的三波入场**。

| 波次 | 时间窗 | 内容 | 时长 / 曲线 | 光扫 |
|---|---|---|---|---|
| **VL1 焦点波** | 0–420ms | 本次解锁的"头条"元素（如整个右栏面板展开时的主角卡） | 420ms `cubic-bezier(.22,1,.36,1)` | **有** |
| **VL2 支撑波** | 60–660ms | 支撑性控件（每项 +60ms 交错） | 380ms `cubic-bezier(.22,1,.36,1)` | 无 |
| **VL3 后置收尾** | 240–840ms | 次要面板（简单淡入） | 300ms `ease-out` | 无 |

```css
.reveal.vl1{ --rv-delay:0ms;   animation-duration:420ms; }
.reveal.vl2{ --rv-delay:60ms;  animation-duration:380ms; }
.reveal.vl3{ --rv-delay:240ms; animation-duration:300ms; }
.reveal.vl3::after{ display:none; }        /* 后置波不做光扫 */
```

**交错上限**：第 6 项起统一 `--rv-delay:300ms`，否则 8 个预设每个 +60ms，最后一个要等 420ms 才开始 —— 玩家会以为卡住。

```css
.reveal:nth-child(1){ --rv-delay:0ms; }
.reveal:nth-child(2){ --rv-delay:60ms; }
.reveal:nth-child(3){ --rv-delay:120ms; }
.reveal:nth-child(4){ --rv-delay:180ms; }
.reveal:nth-child(5){ --rv-delay:240ms; }
.reveal:nth-child(n+6){ --rv-delay:300ms; }
```

### 6.4 揭示方向（语义化的"从哪来"）

方向不是随便选的，它告诉玩家「新东西来自哪个方向」：

| 解锁内容 | 方向 | 初始 transform | 语义 |
|---|---|---|---|
| 右栏面板（滑块/预设/局势/放大） | **自上向下** | `translateY(-8px)` | **与文策渊 §11.2 `unlockIn` 一致**（右栏从上方展开） |
| 左栏下方（曲线/记录/工具） | **自下向上** | `translateY(8px)` | 位于培养皿下方，从下方浮现 |
| 卡内新增控件（如第 4 个工具） | **自左向右** | `translateX(-6px)` | 在原控件后方"续上"，符合阅读顺序 |

```css
.reveal.from-top   { --rv-from:translateY(-8px); }
.reveal.from-bottom{ --rv-from:translateY(8px);  }
.reveal.from-left  { --rv-from:translateX(-6px); }
```

> **与文策渊对齐**：文策渊的 `unlockIn` 用 `translateY(-8px)`（自上向下），本方案**沿用它作为右栏默认方向**，仅在左栏下方元素上用"自下向上"。这样文策渊的钩子可直接复用、不需改写。

### 6.5 两档选择表（何时用文策渊的 .22s，何时用本节的 420ms）

| 场景 | 用哪个 | 理由 |
|---|---|---|
| 单个低权重元素出现（如 Tier 2c 加一个"化疗药量"滑块） | **文策渊的 `.22s ease`** | 低调、不喧宾夺主 |
| 解锁新 tier 的**整批**元素（Tier 1→Tier 2、Tier 2→Tier 3） | **本节的 VL1/VL2/VL3 三段节奏** | 这是"奖励事件"，值得 840ms 的仪式感 |
| `⚙ 专家模式` 一键全开 | **本节的 VL3 简单淡入（300ms）** | 老玩家不需要仪式，要的是快（文策渊 §A6 要求 ≤100ms 响应 → 动画不阻塞可见性） |

```css
/* 整层解锁：加 .tier-unlock 到 body，触发三段节奏 */
body.tier-unlock .card.reveal-card{ animation: revealCard 480ms cubic-bezier(.22,1,.36,1) both; }
/* 单项解锁：保持文策渊的轻量钩子 */
.card[data-tier].solo{ animation: unlockIn 220ms ease both; }
```

### 6.6 完整时间轴（Tier 1→Tier 2 解锁示例）

```
  0ms ─┬─ VL1：右栏首卡自上向下滑入开始（420ms，cubic-bezier(.22,1,.36,1)）+ 光扫
       │
 60ms ─┼─ VL2：支撑控件第 1 项揭示（380ms）
120ms ─┼─ VL2：第 2 项 + 第 1 项光扫启动（720ms）
180ms ─┼─ VL2：第 3 项
240ms ─┼─ VL3：次要面板淡入（300ms ease-out）+ VL2 第 4 项
300ms ─┼─ 其余项（交错封顶）
540ms ─┼─ VL3 落定
840ms ─┴─ 光扫全部结束 → W1 引导焦点脉冲接管（2400ms 循环）
```

**总时长 840ms**，上界 ≤1s。**文策渊 §12 A4 要求"完成第 1 题后 ≤1s 内 Tier 2 元素滑入"—— 本方案 840ms 满足。**

### 6.7 无动画降级

```css
@media (prefers-reduced-motion: reduce){
  .reveal, .card.reveal-card, .card[data-tier], .card.solo{
    animation-duration: 1ms !important;
    animation-delay: 0ms !important;
  }
  .reveal::after{ display:none; }
  .w1-cta{ animation:none !important; }
  .card{ transition-duration:80ms !important; }
  .dishwrap::after{ transition-duration:80ms !important; }
}
```

> **降级后仍保留"出现"的语义**（元素照样出现，只是不飞不扫），**不保留**任何循环动画。满足 WCAG 2.3.3 与 2.2.2。
> ⚠️ **与文策渊 §11.7.4 的整合**：文策渊要求 reduced-motion 下**保留**「裂解定格」慢动作（那是内容不是装饰）。**我同意** —— 本节的降级只关动画与过渡，**不涉及文策渊的慢动作逻辑**（`devSpeed` 临时调整），两者不冲突。

```js
/* 由文策渊侧实现：LAYERS 是唯一数据源，注入 data-tier + 权重 class */
var LAYERS = {
  /* id            : 归属 Tier（唯一需要维护的数字） */
  '#dish'         : 1, '#missionCard': 1, '#btnPlay': 1,
  '#evt'          : 1, '#hint2'      : 1, '#hud'    : 1,

  '#envCard'      : 2, '#inspCard'   : 2, '#mileCard': 2,
  '#speedCard'    : 3
};
function injectTiers(){
  Object.keys(LAYERS).forEach(function(sel){
    document.querySelectorAll(sel).forEach(function(el){
      el.setAttribute('data-tier', LAYERS[sel]);   /* 唯一属性来源 */
    });
  });
}
```

**我侧只消费两样东西，绝不手写 tier 数字：**
